## Oracle DA2 implementation

A database management project built using **Oracle SQL, PL/SQL, Python, and Flask**. It provides a local web interface for managing household finances, bank accounts, investments, subscriptions, savings goals, and financial transactions.

Developed as a **DBMS DA2 Implementation Project**, based on an Entity-Relationship (ER) diagram converted into a relational database.

## Features

- **Interactive Dashboard:** Displays the available database tables and their record counts.
- **CRUD Operations:** Insert, view, update, and delete records through a browser-based interface.
- **12 SQL Reports:** Demonstrates JOINs, aggregate functions, subqueries, and financial data analysis.
- **PL/SQL Functions:** Calculates savings goal completion percentages.
- **Stored Procedures:** Validates and inserts new transactions.
- **Explicit Cursors:** Retrieves and displays transaction history.
- **Database Triggers:** Automatically updates account balances and maintains transaction audit logs.
- **Data Integrity:** Implements primary keys, foreign keys, CHECK constraints, and relational ownership rules.

## Database Design

The database is based on 10 conceptual entities from the original ER diagram, mapped into **11 business tables and 1 supporting audit table**.

| Table | Description |
|---|---|
| PF_HOUSEHOLD | Stores household information |
| PF_USERS | Stores user details and household membership |
| PF_BANK | Stores bank information |
| PF_ACCOUNT | Stores account owners, account types, and balances |
| PF_COMPANY | Stores company details |
| PF_SHARES | Stores shares issued by companies |
| PF_USER_SHARES | Maintains user shareholdings |
| PF_SUBSCRIPTION | Tracks recurring subscription payments |
| PF_GOAL | Stores savings goals and target amounts |
| PF_CATEGORY | Classifies transactions and goals |
| PF_TRANSACTION | Records income and expense transactions |
| PF_TRANS_AUDIT | Maintains transaction history generated by triggers |

**Important database concepts implemented:**

- One-to-many and many-to-many relationships
- Primary and foreign keys
- Composite primary keys
- Referential integrity
- CHECK constraints
- Views and database sequences
- PL/SQL procedures, functions, cursors, and triggers

## PL/SQL Implementation

The project includes the following stored database programs.

**1. PF_GOAL_PROGRESS (Function)**

Calculates the percentage of a savings goal that has been completed.

**2. PF_ADD_TRANSACTION (Procedure)**

Validates and inserts a new income or expense transaction, returning the generated transaction ID.

**3. PF_PRINT_ACCOUNT_HISTORY (Cursor Procedure)**

Uses an explicit cursor to retrieve and display the transaction history of a particular account.

**4. PF_TRANSACTION_BALANCE_TRG (Trigger)**

Automatically executes after INSERT, UPDATE, or DELETE operations on the transaction table.

It adjusts the corresponding account balance and records the operation in `PF_TRANS_AUDIT`.

**5. PF_ACCOUNT_OVERVIEW (View)**

Combines account, bank, and ownership information into a reusable SQL view.

## Installation and Setup

### Prerequisites

- Python 3.10 or newer
- Oracle Database
- Oracle SQL Developer
- Python pip
- Docker Desktop (optional, for running Oracle locally)

For detailed Oracle installation instructions, refer to `SETUP_GUIDE_WINDOWS_UBUNTU.md`.

### Step 1 — Configure Oracle Database

Connect to Oracle using SQL Developer with a dedicated project database user.

Execute the SQL scripts in the following order:

```text
1. 01_schema.sql
2. 03_plsql.sql
3. 02_seed.sql
4. 04_queries.sql
```

Use **F5 (Run Script)** to execute each file.

These scripts create the database tables, PL/SQL components, sample records, and SQL reports.

Run the initialization scripts only once for a fresh database.

### Step 2 — Install Python Dependencies

Open a PowerShell terminal in the project directory.

Create a virtual environment:

```powershell
python -m venv .venv
```

Install the required packages:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### Step 3 — Configure Database Connection

Create a `.env` file using `.env.example`:

```powershell
Copy-Item .env.example .env
```

Configure your Oracle connection:

```dotenv
ORACLE_USER=your_project_username
ORACLE_PASSWORD=your_project_password
ORACLE_DSN=localhost:1521/FREEPDB1
FLASK_SECRET_KEY=replace_with_a_random_local_secret
APP_HOST=127.0.0.1
PORT=5000
```

Use your own Oracle database credentials.

**Never upload the `.env` file to GitHub.**

### Step 4 — Verify Database Connectivity

Execute:

```powershell
.\.venv\Scripts\python.exe check_connection.py
```

This checks the Oracle connection, project tables, and sample data.

### Step 5 — Start the Website

Run:

```powershell
.\.venv\Scripts\python.exe app.py
```

Open the application in your browser:

**http://127.0.0.1:5000/**

Diagnostic endpoints:

- `/health` — Checks whether the Flask server is running.
- `/db-check` — Checks connectivity to Oracle.

For Linux, use `python3 -m venv .venv` and `.venv/bin/python` instead of the Windows Python path.

## Application Workflow

1. Open the website dashboard.
2. Select a database table.
3. View the existing records.
4. Use the Add, Edit, or Delete controls to perform CRUD operations.
5. Open the Transactions section to record income or expenses.
6. Observe automatic balance updates performed by the database trigger.
7. Open the **12 SQL Reports** section to execute and display financial reports.

The frontend communicates with Oracle through the Python Flask backend.

## Example: Transaction Trigger

When a user inserts an expense transaction through the website, the Flask backend sends the INSERT operation to Oracle.

The database trigger automatically deducts the expense from the associated account balance and records the operation in the audit table.

Updating or deleting the transaction adjusts the balance accordingly.

This demonstrates the integration of **Frontend → Python Backend → Oracle SQL → PL/SQL Trigger**.

## Project Scope

This is an educational database application developed to demonstrate relational database design, SQL querying, PL/SQL programming, and frontend-backend connectivity.

The application is intended for **local classroom demonstration only**. It does not implement user authentication or CSRF protection and should not be exposed directly to the public internet.
